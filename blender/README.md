# Blender building pipeline

Everything in `public/models/city-kit/` and `public/models/homes/` (except the
GLB-and-atlas outputs themselves) is generated by the scripts here, so the models
are *code*: change a number, re-run, get new buildings.

```sh
pip install -r blender/requirements.txt          # bpy is Blender as a Python module (Python 3.13)
npm run build:buildings                          # towers+blocks (city) and houses+trees (homes)
npm run build:ground                             # the repeating street/lawn cell under the homes
npm run build:clouds                             # the cloud-sea HDR the homes are lit and reflected by
npm run bake:rings                               # then re-partition the lots into LOD rings
```

`python blender/make_buildings.py --set homes --only home-tudor --debug /tmp/maps`
rebuilds one module and dumps every texture map as a PNG. The same scripts run
inside the Blender UI: `blender -b -P blender/make_buildings.py -- --set city`.
`blender/blend/*.blend` hold the low-poly shells (open them to look at the models).

## Two meshes per building

Each module is built **twice** from one description:

- a **low-poly shell** that ships: a few dozen to a few hundred triangles of walls,
  roof planes, setbacks, crowns, masts, porches and chimneys;
- a **high-poly twin** that never ships: real window reveals, mullions, sills,
  shutters, door steps, fascia, balconies, rooftop plant, and materials with
  metre-scale clapboard, brick and shingle patterns.

Cycles then bakes the twin onto the shell, and everything lands in **one shared
atlas per set** (one material, one draw call per module type):

| map | contents |
| --- | --- |
| `atlas-color` | albedo, with some of the bounce-aware occlusion folded in |
| `atlas-orm` | R = occlusion, G = roughness, B = metalness (glTF packing) |
| `atlas-normal` | tangent-space normals from the real reveals and trim |
| `atlas-emissive` | lit windows (warm and cool rooms, whole dark floors) |
| `*-low` | half-size colour/ORM/emissive for phones, which skip the normal map |

The occlusion is **path-traced multi-bounce diffuse light under a uniform sky**,
not plain AO: an open surface bakes to 1.0, a cavity to what light actually reaches
it after bouncing around the reveals and balconies.

## Layout of the code

```
make_buildings.py   entry point: build -> UV -> bake -> export (one --set at a time)
make_cloud_env.py   path-traced cloud sea + cumulus -> public/hdri/cloud_env_1k.hdr
make_ground.py      numpy/Pillow: the seamless street-and-lawn cell (no Blender)
bld/
  geo.py            wall-local frames, boxes, quads, cylinders, spheres
  materials.py      the material table + the bake-pass swaps (see below)
  facade.py         tower facades: curtain wall, punched, deco, ribbon, steel, louvre, shopfront
  roofs.py          flat roofs: parapets, plant, skylights, solar rows, helipads
  house.py          house walls with real openings, gable/hip roofs, porches, chimneys, dormers
  homes.py          the twelve houses     trees.py   the four trees
  archetypes.py     the eight towers and four blocks
  model.py          the low/high pair, UV assignment, bake proxies
  atlas.py          sheet layouts and the rectangle packer
  bake.py           the Cycles passes and map assembly
```

## How the bake stays exact

The high-poly materials are never rendered with lighting. Each pass swaps every
material for an Emission shader that outputs exactly the quantity being baked
(albedo, a packed roughness/metalness colour, the lit-window glow), so the atlas
holds the material table's values, not a lighting result. Lighting is the runtime's
job. The only lit pass is the occlusion one.

Faces that share a texture slot (opposite walls of a tower) are identical by
construction, and the bake uses one representative per slot with every face on its
own vertices, so the cage extrudes straight out of each face.

## What is baked, and what deliberately is not

Baked: facade and roof detail, lit windows, occlusion with bounces, the cloud-lit
sky (as an environment map) that the homes take their light and reflections from.

**Not** baked: the sun, and shadows from it or from clouds. Its direction changes in
every chapter and each module is instanced at four rotations, so a sun baked into a
shared atlas would be wrong on three of the four. The engine keeps a real
directional light for it. The cloud environment is rendered *without* a sun disc for
the same reason (the clouds are still lit by a sun, so they glow and have silver
edges on the sun side).

## Coupling to the site

- Module ids containing `sky` are the tall lots in `cityGen.mjs`; `kind` in the
  manifest (`house` / `tree`) selects `homeLots`.
- `blender/make_ground.py` and `HOME_CELL` in `src/webgl/bake/cityGen.mjs` describe
  the same grid; change one, change the other. `LAMPS` here is mirrored in
  `Rooftops.ts`.
- Modules are exported at fixed scale (`SCALE` in `homes.py`) or normalised to a
  target size (`target` in `archetypes.py`); the lot maths depends on which.
